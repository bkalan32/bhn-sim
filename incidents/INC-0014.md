# INC-0014 — Tier-2 drill: bad deploy, rollback proposed by automation, approved by a human (Day 12)

The velocity-check release again (Days 6, 8, 10) — this time shipped with the pipeline's
Verify **skipped**, so nothing rolled it back automatically. The incident path did:
`ActivationHighErrorRate` → the remediator saw a deploy of activation minutes earlier (the
bot's deploy collector) → **PROPOSED** a rollback with a capability token → a human approved
it → `rollout undo` ran as the remediator's ServiceAccount → alerts resolved → **RECOVERED**.

Two runs. Run #1 found a bug in my Role; run #2 is the clean number. Both are kept.

own cycle. Two clocks: **production was healthy ~60 s after approval; the system knew ~5 min
later.** The KPI table records both.

## The timeline reads like a story
alert → proposal → human approval → action → recovery. Every step on one record, with times,
written by the automation itself. During a bridge, "what has the automation already done?"
has an instant answer.

## Approve-to-recover, next to the benchmarks
| Path | What recovers production | approval → production healthy | alert → alert resolved | human effort |
|---|---|---|---|---|
| Day 6, manual | a human reads the dashboard, finds the deploy, types `rollout undo` | not timed on Day 6 (INC-0006 says `_N_`); ~30 s of rollout + however long the finding took | – | find the cause, decide, type |
| Day 6/10, pipeline Verify | Verify's 120 s wait + ~30 s rollback, **before any alert** | n/a — recovers before detection; deploy → healthy ≈ 2.5 min | n/a | none — but only for releases that go through the pipeline |
| **Day 12, tier 2 (run #2)** | proposal + one human yes | **~60 s** (13 s to execute, then the rate window) | **389 s** | read one note, run one command — 35 s |
| Day 12, tier 2 (run #1) | same, verification forbidden | ~60 s (the rollback itself) | 1102 s (185 s of it a timeout) | 686 s of human reading |

The honest comparison: the pipeline path is faster *for deploys*, because it does not wait for an
alert. The tier-2 path covers what the pipeline cannot — a bad release that slipped past Verify,
a config change, a rollback needed an hour later — and it turns "find the cause, then decide,
then type" into "decide". The automation's own share of the loop is 28 s (alert → proposal) plus
13 s (approval → verified rollback); everything else is either the human or the alert windows.
